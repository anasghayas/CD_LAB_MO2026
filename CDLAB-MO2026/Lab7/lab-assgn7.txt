P2. The parser of P1, accepts all declarations that are syntactically valid, but is not capable of detecting semantic
errors in declarations. An essential requirement for detecting semantic errors in declarations is to save the
attributes of all declarations that are both syntactically and semantically valid in some data structure D. When an
unknown syntactically valid declaration is parsed, its semantic validity can be checked with those saved in D. In
case the new declaration is semantically valid, it is to be saved in D, otherwise issue an error message, skip this
declaration, and continue parsing. A hash table is known to be an efficient choice for D, however in our
experimentation, we shall use a simple sequential table for ease of implementation. The structure of the symbol
table, is drawn in problem P3 below.

Bonus Problem Consider grammar G, with nonterminals {start dlist decl type elist}, terminals {ID SHORT
DOUBLE , ; } and 8 rules as given below.
start →dlist
dlist →dlist decl | decl
decl →type elist ';'
elist →elist ',' ID | ID
type→ SHORT | DOUBLE
The symbol table structure remains the same as that of P3. The difference in P4 is that all identifiers in a single
declaration statement are first collected into a list and the list appended to the symbol table in a single call to
append(). You would need to define a list data structure for this solution. Outline of the design involves creating
a single element list using makelist() and append() to add new elements at the end of the list. Semantic checks
have to be added at appropriate places in the actions to ensure that semantic errors are detected and reported.
Some nonterminals may have a list data structure associated as its attribute as shown below.
elist →ID {elist.list = makelist (ID.name);}
| elist1 ',' ID {elist.list = append(elist1.list, ID.name);}
decl →type elist ';' {insert(symtab, elist.list, type.name, type.width, offset, ….); ...}
