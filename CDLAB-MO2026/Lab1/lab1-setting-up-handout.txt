are present in the kernel data structure of a directory. The "ls" command displays several attributes

several useful switches and we explain here the form "ls ‒al", where " ‒l" stands for long form
description and "‒a" stands for all entries of the argument directory.

4.6 Third and Fourth Fields : Displays the identity of owner and group of owner.
Every file resource in Linux is assigned two owners by default – one is the identity of the user who is
the creator of the resource, denoted as "uid", and the other is the identity of the group, denoted by

"gid", to which the user "uid" belongs to. For example, "uid" for a student is denoted in this handout as
"you”, while "gid" of a student is also denoted as "you”, which may be different in your system. In
practice, a student of your batch may have uid as her/his "roll-number” and gid as "btech3” indicating a
3rd year B Tech student. For a faculty member, the uid and gid respectively may be, "sb" and "fac", to
represent "Supratim Biswas" and his group as "faculty". The gid specifies the privileges accorded to the
different groups in the file system and every user in the group is constrained by these predefined
privileges.
4.7 Fifth Field : Size of the directory in bytes.
A directory may be visualized as a tabular data structure, and the size of a directory determines the
maximum number of entries in it. Assuming each entry of the directory occupies 4 bytes, 4096 denotes
that the directory can have as many as 1024 entries (files or directories). Since the first 2 entries of
every directory are reserved for "•" and "••”, current and its parent directory, it implies that 1022 other
distinct entries may exist in it. It may be noted that the actual internal data structure of a node in the
Linux file system (directory or a file) has several other attributes, but "ls" is permitted to read only a
few fields from this kernel data structure and display them.
The size 4096 is used here as the default size allocated to every directory on creation, that is empty
except the first 2 mandatory entries. However this is not a limitation, since when an user has adds more
than 1024 entries in a certain directory, the OS allocates another chunk of 4096 bytes, to make it 8192
bytes, in order to let it grow further (though having a large monolithic organization is not considered a
good design).
4.8 Sixth and Seventh Fields : Date and time of creation of a resource
The time stamp of a resource is a field in the internal kernel data structure. Not only the time stamp of a
resource at the point of creation is saved, time stamps related to latest access and last modifications of
the resource are also preserved. The "ls ‒l" command displays the creation time stamp only, which
comprise the date, month and year of creation, along with the time in hours and minutes, for every
resource in the directory.
For resources recently created, say within the last 6 months, it does not show the year while for older
ones it shows the year but suppresses the time. Consider the following displays from "ls ‒l" from some
directory.

4.5 Secure your home directory
The home directory of an user (referred to as home-dir, "/home/roll-no") can be secured to ensure that
this directory can not be accessed by any other user in the system, except the administrator. This will
prevent copying of resources in the file system rooted at the home-dir of an user, intentionally or
otherwise, by other users in the system. This is possible if we know how to change the default access
permissions set by your OS. In Linux OS, the command "chmod", does this task. The usage of chmod
is
chmod <person> <new-perms> <name>
The candidates for <person> are u(user), g(group), o(others). Any subset of {u, g, o} may be given. The
candidates for <new-perms> are defined by + (to add) or ‒ (to remove) a permission, followed by one
or more of read(r), write(w), execute(x). The <name> attribute is the the name of the resource whose
permissions need to be changed.
Example : Let the permission of "/home/you" be as given below.
drwxrwxr-x 3 you you 4096 Jul 29 08:42 /home/you
i) The command
$ chmod g‒w /home/you
specifies that the write access for group(g) is to be removed for the directory /home/you. This
command changes the permissions as shown below.
drwxr-xr-x 3 you you 4096 Jul 29 08:42 /home/you
(ii) To add write permission to both g and o, we execute the command :
$ chmod go+w /home/you
which changes the listing to
drwxrwxrwx 3 you you 4096 Jul 29 08:42 /home/you
(iii) To prevent others, both g and o, to access /home/you, we issue the command :
$ chmod go‒rwx /home/you
which results in
drwx------ 3 you you 4096 Jul 29 08:42 /home/you
